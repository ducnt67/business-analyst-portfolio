# Harvard-style CV skill

Use this skill to produce or review a clean, evidence-based CV commonly associated with Harvard resume guidance. Treat “Harvard CV” as a practical style convention, not a guarantee of official Harvard endorsement or a universal requirement. Always follow the target employer, school, country, and job description when they conflict with a generic convention.

## Operating principles

- Optimize for fast scanning, factual accuracy, relevance, and evidence of impact.
- Prefer simple, text-first layouts that parse reliably in ATS systems.
- Do not invent employers, dates, metrics, titles, grades, certifications, links, or responsibilities. If a metric is missing, ask for it or use a clearly marked placeholder.
- Tailor the document to the target role. Relevance outranks completeness: remove impressive but unrelated material when space is limited.
- Preserve the user's language and level of seniority. Use English section labels or bilingual labels only when appropriate for the target audience.

## Choose the right mode

1. **Create**: build a CV from raw background information.
2. **Rewrite**: retain the user's facts while improving structure, wording, evidence, and prioritization.
3. **Audit**: identify defects, explain why they matter, and propose precise corrections.
4. **Tailor**: compare the CV with a job description and prioritize matching skills, keywords, and achievements without keyword stuffing.

For detailed rules and the final review checklist, read [references/rules-and-checklist.md](references/rules-and-checklist.md).

## Default workflow

1. Identify the target role, employer or program, location, seniority, and submission requirements. If unavailable, state the assumption.
2. Extract only verified facts from the user's materials and separate facts from claims that need confirmation.
3. Select the strongest relevant evidence and order sections for the candidate's profile. For students and recent graduates, Education may precede Experience; for experienced candidates, Experience normally leads.
4. Draft each experience bullet around the XYZ pattern: **achieved X, measured by Y, by doing Z**. Start with a strong action verb, show the result, and explain the method or scope.
5. Apply a restrained, ATS-friendly layout and keep the document within the appropriate length.
6. Run the checklist: factual consistency, dates, contact details, spelling, tense, metrics, relevance, page length, parsing, and PDF export.
7. Report unresolved gaps instead of silently filling them. Offer targeted questions or placeholders for missing evidence.

## Experience bullet standard

Use 3–5 bullets for a substantial role when space allows. Prefer:

`Action verb + task/intervention + measurable result + scope or method`

Good evidence may include percentages, revenue or cost, volume, time saved, users, team size, budget, ranking, accuracy, cycle time, or before/after comparison. Not every bullet must contain a number when the result is genuinely qualitative, but the document should make impact concrete wherever possible.

Avoid “Responsible for”, “Worked on”, vague self-descriptors, duty lists, inflated claims, unexplained acronyms, and repeated bullets across roles.

## Output expectations

- When creating a CV, provide the finished content in a usable structure and clearly label placeholders.
- When auditing, classify findings as **critical**, **high-impact**, or **polish**, and give a corrected example where possible.
- When tailoring, explain which evidence was prioritized and which content was deprioritized.
- If the user requests a file, preserve the same content rules and perform a final visual and text-level QA appropriate to the file format.
